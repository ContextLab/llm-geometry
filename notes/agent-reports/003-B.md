## RNG / preset portability decision

- **Native (bit-exact f32)**: `identity`, `toeplitz_fuzzy`, `zero`, `learned`. Every numpy float32 op is mirrored with `Math.fround` (double-rounding through f64 is exact for +,*,/,√ since 53 ≥ 2·24+2); verified bit-equal against numpy empirically and via exact token equality.
- **Fixture-served**: `random`, `random_autocorr` need numpy's PCG64+ziggurat (and scipy `gaussian_filter`) streams — not portable at the bit-exactness the content hash demands. `presetFixtures.json` ships the REAL `preset_matrix()` outputs (base64 f32-LE) for **seeds 0, 1, 2, 7** (7 because 003-A's goldens use it). Other seeds throw `InvalidWeightEditError` with an explicit message. **UI contract: static WeightLab must restrict random/random_autocorr seeds to `fixtures.seeds`.** One RNG stream serves all four 3×3 matrices per seed (backend behavior).
- **Fine-tune RNG**: torch.randperm is not portable; static mode shuffles with its own sfc32(seed+1) (documented in finetune.ts). Tests assert trajectory properties, not bit-equality.
