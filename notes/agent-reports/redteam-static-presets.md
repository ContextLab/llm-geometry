Date: 2026-07-24 · Target: `http://localhost:4173/llm-geometry/` (vite preview of `code/frontend/dist`, real Pages base path, no backend) · Harness: throwaway Playwright scripts in `/private/tmp/rts-presets/` (SwiftShader), screenshots in `/private/tmp/rts-presets/shots/`, exports in `/private/tmp/rts-presets/exports/`, network/console logs in `/private/tmp/rts-presets/*-netlog.json`. ## Findings

### F1 — HIGH (honesty + robustness): one ↻ Recompute click permanently blanks each 001 view on its next mount, behind a false "not precomputed" notice
Repro (100% deterministic, no model switch or thrash needed — script `08-true-minimal.mjs`):
1. Load the app (vector preset 1 renders, 1152 arrows). 2. Click **↻ Recompute** once. 3. Switch to any other tab, then back to Vector field.
Result: blank panel (`viz-vector data-ready=0`, 0 arrows) under the StaticNotice *"…this exact request is not one of them"* — while model/prompt/temp/layer/picker sit **exactly on preset 1** ("Default · layer 0"). Clicking Recompute again does NOT recover (re-forces, stays blank). Recovery only via selecting a *different* preset (then back — `07-recovery.mjs`) or a full reload.
- Cross-view: `refreshNonce` is global, so a single Recompute on the Sankey tab also blanks Manifold on its next mount (`09-sankey-manifold-recompute.mjs`: sankey away+back → `ready=0`; manifold then never reached `ready=1` in 30 s).
- Root cause (code read, not guessed): each view keeps `let lastRefresh = 0` and computes `force = rn !== lastRefresh` — `VectorField.svelte:43,54-57`, `Sankey.svelte:34,62-63`, `Manifold.svelte:62,595-596`. After any Recompute, `refreshNonce > 0`, so **every remount** starts with `force=true`; `load(..., force)` skips `ensureArtifact` and requests `force: true`, which the static client never matches → `StaticModeError`; on a fresh mount `data=null` → blank + stale miss note. FR-203 violation: the notice asserts a state is not precomputed when it is, over an empty panel.
- Lesser included bug: even without remount, Recompute on a pristine preset immediately shows the same misleading notice (field stays). In static mode the button can never succeed; it should be hidden/disabled or given an honest static message, and `lastRefresh` should init to the current nonce on mount.
- Evidence: shots `70-after-recompute`, `71-after-roundtrip`, `40-thrash-repro-final`, `60-D-broken`, `72-sankey-recompute-roundtrip`. (This also explains the one thrash "hang" in `03.out` — that script had clicked Recompute earlier; thrash without a prior Recompute is clean, `03b`/`05`.)

### F2 — MEDIUM-LOW (export quality): Manifold PNG export is transparent-background (renders white) and not high-res
`exports/manifold-manifold.png` = 743×480 RGBA, transparent bg, washed-out vs the in-app dark scene; vector/sankey PNGs = 1486 px wide, dark bg, correct. Cause: `ExportBar.svelte:66` calls `exportCanvasPNG(webglCanvas()!)` — a bare `canvas.toBlob` (`exportFigure.ts:66-68`) that skips `webglToCanvas()` (`:71-79`), the helper that composites `BG=#0b0e14`; no 2× upscale either, despite the "High-res PNG" title.

### F3 — LOW (observation): vector preset 2 sidebar says "Fan-out 2 arrows / vertex" while the caption says "576 grid arrows · fan-out 1"
Not dishonest: the recorded request asked `fanout: 2` at T=0 and the backend genuinely returned `count=576, fanout=1` (`presets/vector/2.json`); the caption reports the artifact truthfully. The *control* label is what disagrees with the data shown.

### F4 — INFO (deep links): no tab state in the URL; reload on any tab returns to Vector field. vite preview serves index.html (HTTP 200) for any subpath (`/llm-geometry/sankey`, even `/llm-geometry/nonexistent-page`); `dist/` has no `404.html`, so on real GitHub Pages such URLs would 404. No impact — the app never emits subpath URLs. `/llm-geometry` (no slash) → 404 in preview; real Pages redirects.

### F5 — INFO (offline): all 12 preset payloads are prefetched at boot, so after load, `setOffline(true)` degrades nothing — preset switching (incl. never-viewed preset 3), hovers, exports all keep working with zero failed requests; back online stays clean (`03b`, shots 35/36). Honest by construction; cold-start offline is the browser's problem, not the app's.
