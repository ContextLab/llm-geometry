# Feature 005 — explaining the visualizations

**Date**: 2026-07-26 · **Branch**: none (landed on `main`) ·
**Spec**: `specs/005-explain-the-visualizations/spec.md`
**Goal**: updated and fully reviewed live site.

## What was asked

A colleague of the owner — a researcher in this area — opened the deployed site and
could not tell what was being shown. The ask: an Info tab, plus plenty of explanatory
text inside each tab so a reader knows exactly what is on screen, what can be
manipulated, and what the impact of each control is. Audience is assumed
**mathematically sophisticated**, so equations are stated rather than analogized.

## What shipped

- **Info tab** (`src/viz/info/InfoTab.svelte`) — framing, notation, the Architecture
  Explorer (graph provenance, breakdown, decoding), the Geometry Lab (why d=3, the
  forward pass as equations, both fields, the tangency subtlety, a control table, the
  training recipe, bundles), a what's-real/where-it-runs table, known limits with their
  issue numbers, and four verified references.
- **`src/lib/Explain.svelte`** — a `<details>`-based disclosure used by both tabs. Native
  element: works without JS, keyboard-reachable, findable by in-page search.
- **Both explorer tabs** — the always-visible header prose was rewritten from a
  one-liner into real orientation, plus collapsed deep-dives placed next to what they
  explain (2 in Architecture, 3 in Geometry) and a `panel-note` in each of the three
  Geometry cards.

Math is set in Unicode + CSS rather than KaTeX: the static build's CSP would have meant
self-hosting KaTeX's fonts (the same problem already solved for the ONNX runtime) for a
purely typographic gain.

## Things I got wrong while writing it, and caught

Worth recording, because all three were confident sentences that were simply false:

1. **"⟳ spin stops the rotation."** Auto-rotation is OFF by default (`GeoScene.svelte:30`);
   the button *starts* it. Caught by reading the component instead of trusting the label
   I remembered.
2. **"Fine-tune: Adam."** `geo/finetune.py:167` is plain `torch.optim.SGD`. The canonical
   *training* run uses Adam (`geo/train.py:164`) — two different code paths, one wrong
   sentence.
3. **"scratch epochs: up to 60."** The API allows 60 (`SCRATCH_MAX_EPOCHS`), but the
   slider a reader actually touches is 1–30 (`TrainPanel.svelte:249`). Documenting the
   API limit would have described a control that does not exist.

## The documentation-rot problem

Prose that states constants rots silently. `tests/e2e/docs.spec.ts` reads facts from the
running system — `/api/geo/spec`, the real slider `min`/`max`/`value`, the real controls —
and asserts the prose still agrees. Changing `FINETUNE_MAX_STEPS` or the architecture now
fails CI instead of leaving the site quietly lying.

Two **existing** assertions had to be tightened for the opposite reason: they matched
loose text inside a whole tab, and the new prose would have satisfied them even if the
thing they tested disappeared.
- `geo-view` → `geo-active-model` for "corpus" / "coverage" / "field entropy" (the chips).
- `arch-breakdown` "next-token top-10" → a `data-testid` on the real label.
One locator broke outright (`getByText("antisymmetrize")` matched the control *and* the new
explanation); the control now has a testid.

## What the red team found (and what it cost me)

No CRITICAL, but 8 findings were things I had asserted and not checked. Every one below was
re-verified against the code by hand before being acted on.

**False capability claims (mine):**
- "positional embeddings are directly editable" — `EDITABLE_MATRICES` is
  `(W_Q, W_K, W_V, W_O, embedding)`. No route in the app edits a position vector.
- "two gates have to pass before a checkpoint is accepted" — `MIN_COVERAGE_UNIFORMITY` and
  `MIN_FIELD_DIRECTIONAL_ENTROPY` appear only in `config.py` and in *tests*. `train.py`
  never imports them. They are test assertions, not a runtime gate; the text now says so.
- "click a cell to type a new value" — true for the 3×3 matrices, false for the 1003-row
  embedding. Likewise `zero` is refused for the embedding (a zero row cannot be unit-norm).
- The static weight heat map is not a range read. Over-budget windows — which is every
  full-matrix view — serve a **uint8-quantized** precomputed tile; only the zoomed window
  is an exact float read. The honesty table said otherwise.
- Two Architecture bullets promised live tracing and a 400 ms retrace **on the static
  site**, twenty lines below a `{#if STATIC_MODE}` paragraph saying the opposite. Both are
  branched now.

**Imprecision that mattered:**
- "every probability is computed from the unfiltered distribution" — there are *two*
  unfiltered distributions. The per-token percentage is the temperature-scaled softmax; the
  top-5 alternatives are the model's own softmax with no temperature; and at T=0 the "100%"
  is the greedy decision, not a probability. All three are now spelled out.
- The trace's top-10 is a plain temperature-1 softmax, so "this is what the model would
  sample from right now" was wrong — Chat samples from a narrower distribution.
- "the logit lens because the unembedding is tied" is a non sequitur (the logit lens is
  defined for untied models too). What tying actually buys is that a readout direction *is*
  an embedding point, which is why the answer can be drawn as an arrow on the same sphere.
- "instruct-tuned models park an attention sink on the first token" — two errors: the chart
  plots a **massive activation** (the attention sink is the attention-mass phenomenon), and
  it is not specific to instruct tuning. `gpt2`, a base model, is in our own menu, so a
  reader could falsify it in two clicks.

**A real bug the docs would have papered over.** Fine-tuning tokenizes with the *shipped*
vocabulary regardless of the base model, and saves the result without a vocabulary — so
fine-tuning a from-scratch model lands gradients on the wrong rows and relabels every dot
with Alice's words. That is now [issue #6](https://github.com/ContextLab/llm-geometry/issues/6);
both the panel and the Info tab state the limitation and link to it rather than claiming the
opposite as the panel note originally did.

**Comprehension gaps worth more than the prose fixes:**
- The Geometry explainers were mounted *inside* the phase gate, so during the minutes of a
  first training run the visitor saw a progress bar and nothing else — exactly when they are
  most lost. Hoisted above the gate.
- Every pointer to the Info tab was itself inside a collapsed `<details>`, on a tab labelled
  with one generic word. Added a visible, self-retiring "New here? Start with Info →".
- The app had **one URL**: no way to send anyone a link to the explanation. `view` is now
  mirrored into `location.hash`, so `#info` and `#geometry` work and Back works.
- The **prompt** — the control that conditions both fields — was documented nowhere, and
  nothing said the next-next field is prompt-conditioned rather than an autonomous flow on
  S², or that an arrow's tail is the token's embedding rather than the state the prediction
  came from. Both are now stated in the two places a reader will look.
- Arrow length is renormalized per render (90th-percentile → fixed length) and clipped, per
  arrow class. So scaling `W_V` leaves the picture pixel-identical while the text called
  W_V "the largest visible effect". Documented, with what to trust instead.
- A legend now names every colour on the sphere, using the scene's exact hex values. The
  previous key printed the word "amber arrows" in violet — which is the *other* field's
  colour.
