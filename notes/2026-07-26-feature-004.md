## Root causes (all reproduced in a real browser before fixing)

- **#4** was not a link bug at all: the repository was **private**, so every
  `github.com/ContextLab/llm-geometry` link 404'd for visitors. Made public.
- **#1** had two independent causes: decoding sampled the **full vocabulary**
  (`top_k:0, top_p:1.0`) at T=0.8, drawing from the long tail every step; and the
  default model was 135M. Now top-k 50 ∩ top-p 0.9 + repetition penalty 1.1 in **both**
  runtimes, default Qwen2.5-0.5B-Instruct. "What is the capital of France?" →
  "The capital of France is Paris."
- **#2** was three defects, not one: the playhead **overwrote** the layer selection
  every op; the highlighted node was usually inside a **collapsed** layer group and
  off-screen at the default zoom; and heads were a one-at-a-time `<select>`.
- **#6** was three defects: aggregate forces used raw `W_V` and were never projected
  (max normal residual 0.144); force arrows and the token path both set
  `depthTest:false` so the far side painted over the near side; antisymmetrize
  defaulted off.

**The subtle one, worth remembering:** antisymmetrizing `W_V` does *not* make the
aggregate force tangent where it is drawn. `(W_V−W_Vᵀ)/2` makes each term `W_V z_j`
tangent at `z_j`, but the sum `Σⱼ A_ij·W_V z_j` is anchored at `z_i`. Only projecting
at the anchor makes the drawn arrow tangent, and `normal_residual` is what keeps that
projection honest.

## Architecture decisions

- **Vocabulary is part of the model.** From-scratch training rebuilds the vocabulary
  from the user's text, so token id 17 means different words in different models. The
  vocabulary is therefore stored *with* the weights, and `tokenize`/`trace`/
  `vector_field` resolve the tokenizer from the active `weights_token`. The bundled
  vocab table is re-validated whenever the active model changes — for a scratch model
  the probe legitimately fails and labels fall back to what the API reported.
- **Model bundles** (`geo/bundle.py`, `GeoEngine.exportBundle/importBundle`) are the
  portable form: a `weights_token` only means something to the cache that minted it.
  Validation is strict — a bundle whose weights don't re-hash to its declared token is
  refused, because loading it would pair the wrong vocabulary with those weights.
- **TS↔Python parity, stated precisely.** Objective, optimizer, hyperparameters,
  clipping, S² projection, and vocabulary construction are the same. Random
  initialization is *not* bit-identical (numpy's RNG stream isn't reproducible in JS),
  so a browser run and a Python run from "the same seed" are two independent runs of
  one recipe. The vocabulary test is the strong parity check: `buildVocabWords()`
  reproduces the shipped `vocab.json` word-for-word.
- **HF datasets in the browser** use the Hub's public, CORS-enabled dataset-viewer
  service, with the same text-column choice as the backend.

## Bugs found by driving the UI rather than reasoning about it

1. `GET /api/geo/corpus_stats` with a real 150 KB corpus does not fit in a query
   string — the request failed and the counter silently vanished. Computed locally now.
2. The Geometry header kept describing the **shipped** checkpoint (corpus, final loss,
   coverage) while a scratch-trained or loaded model was driving the sphere.
3. The weight lab called every non-canonical model "edited weights active", including
   scratch-trained and imported ones.
4. The fine-tune panel disabled the HF-dataset tab as "not available in the static
   demo" after that stopped being true.

## Deliberately not done

- Arbitrary HuggingFace models in the picker. The static build needs a community ONNX
  export, which most repos lack, so the old free-text input promised what the deployed
  demo could not keep. Removed; widening the list is **issue #4**.
- Whole-run TS↔Python training equality — not achievable (platform-divergent BLAS,
  non-portable RNG), so it is not claimed.
